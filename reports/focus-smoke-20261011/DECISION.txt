Cluster: 6000 server and 1500 offline commands. Random: 10000 and 2500 commands.
Core history repeatedly replaces the same 128 KiB range: checkpoints after 2, 16 and 64 MiB of inserted AND deleted payload. Visible size remains effectively constant.
Offline client branches before server editing/history; both branches are saved/reloaded and merged; local state is checked against an independent Rope reference, both merged replicas against each other, sentinels and duplicates checked.
Probes use single-operation transactions: 256 local replacements, 512 random replacements, edge edits, 1/10 MiB paste followed by deletion. First edit is measured BEFORE full text materialization. p95/p99 of small sample counts are descriptive, not robust production tail estimates.
Every measured phase is a fresh process owning one CRDT replica. Reference computations run separately. Peaks use Linux VmHWM reset and kernel RSS.
Storage is the actual exported CRDT payload plus optional lossless Zstd-3; both representations exist as benchmark fixtures, but a server needs only the chosen representation plus unapplied updates. No shallow snapshots/history pruning. No old backup snapshots or test-only replicas are included in payload cost.
Raw snapshot writing includes fsync; database indexes, backups, replication, network and Flutter/Web UI costs are not included. Zstd compression/decompression and exact byte roundtrip are verified.
Resource limits: 12 GiB per worker, 4 GiB host RAM reserve, 10 GiB disk reserve. Cases interrupted by time/resource guards remain INCOMPLETE, never counted as passed.
Different scenarios and history volumes must not be combined into one ranking. Exact recipes/versions/source hashes and failures are retained.
